Obelisk Approaches Taxonomy

Context: Multi-year solo pet project evolution. Multiple parallel variants co-exist without git branching. Organized into architectural folders to separate dead-ends from the active winning core.

User Directive #15 (Authoritative): You are allowed to create subprojects and copy code, so all of set_theory_prover has various approaches, and all are implemented. Do not restrict development to a single approach; maintain and develop higher-order types (foundations.ML), sequent calculus (newchecker.ML), and Morse-Kelley calculus (checker.ML) in parallel.

Architectural Approaches (Folders)

  • winning_demo/ (FOUNDATIONAL DEMONSTRATION ENGINE)
    The Winning Core: types/foundations.ML, newchecker.ML, and the dependent type system (dependent_typechecker.ML, obelisk_compiler.ML, verified_theorems.ML). Produces machine-checked proofs.

  • early_checker/ (FIRST-GEN MORSE-KELLEY CHECKER)
    Prototype: early_checker_prototype/checker.ML (5,177 lines). Early sequent calculus engine with 4,941 lines of restored working code preserved for speed/reference.

  • lambda_calculus_strings/ (STRING-AST EXPERIMENTS)
    Dead-End / Archived: String manipulation of lambda terms (lang.ML, lambda.ML). Archived when typed ASTs replaced string syntax.

  • coq_rocq_transpiler/ (EXPERIMENTAL COQ/ROCQ BRIDGE)
    Bridge: Transpilation experiments targeting Rocq/Coq inductive set definitions.
