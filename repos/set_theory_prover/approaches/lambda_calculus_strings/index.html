Approach: Lambda Calculus Strings

Path: program/approaches/lambda_calculus_strings/
Status: CONCLUDED EXPLORATORY DEAD-END

Why Concluded: Early attempts represented lambda calculus syntax directly via string tokens (lang.ML, QUOTE_SML_DEADEND.ML). The author recognized that manipulating formulas as strings causes capture errors, slow evaluation, and fragile typing.

Archived Components

  • lang.ML • language.ML • lambda.ML: Untyped and simply-typed lambda terms encoded via string representations.
  • QUOTE_SML_DEADEND.ML: Experimental quotation parsing directly into SML source code. Concluded as impractical.
  • untyped_lam.ML • program.ML: Redundant lambda normalization evaluators.

Lessons Learned

String ASTs were abandoned in favor of structured SML datatypes (datatype Term in dependent_syntax.ML and nbg_compiler.ML), enabling capture-avoiding substitution and Milner-style LCF kernel invariants.
