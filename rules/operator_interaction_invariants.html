Operator Interaction & Command Invariants

Rationale: Distilled from empirical analysis of historical user command trajectories, model outcomes, and regression cycles (especially sessions b183e4f4 and 5b94e013). These invariants govern command interpretation, task scoping, and delivery gates to eliminate conversational friction, token waste, and recurring regressions.

Category 1: Command Scoping & Anti-Drift Invariants

  1. Boundary Invariant (Anti-"Carte Blanche"): Never interpret open-ended permission phrases (e.g., "do whatever you want, but be reasonable") as license to alter established syntax styling, invent ad-hoc compound Unicode notations, or merge separate conceptual theories. Always define and respect explicit boundaries and preserve existing aesthetics.
  2. Single-Layer Separation Invariant: Decouple changes across architectural strata:
    • Stratum A: Mathematical AST / SML Kernel (e.g., constructors, proof rules in set_theory_prover).
    • Stratum B: SML Formula / LaTeX Emitters (e.g., html_generator.ML, nbg_html_generator.ML).
    • Stratum C: Web Presentation / CSS & DOM (e.g., embedding.html, MathJax configuration, mobile responsive panels).
    • Stratum D: Infrastructure / Git / Platforms (e.g., reverse proxy, GitLab, backup scripts).
    Never execute multi-stratum compound bug reports in an unverified single turn.
  3. Goal-Anchored Continuation Invariant: Never treat a bare continue command as an open-ended refactoring license. Every continuation must anchor to a concrete ticket, subsystem, or file, run required tests, and immediately stop once verified.
  4. Curated External Critique Invariant: When external AI evaluations (e.g., Claude tickets T1–T6, W1–W6) are pasted, audit them against /botworkspace/FACTBOOK.md and user directives before acting. Reject suggestions that assume incomplete repository context (e.g., replacing Dunaev pairs with Kuratowski pairs, or erasing MK/NBG distinction).

Category 2: Rendering & Syntax Generation Invariants

  1. MathJax TeX Catcode 6 Invariant (No Raw # in Math Mode): TeX reserves # for macro parameters inside math delimiters \( ... \) and $$ ... $$. SML generators must NEVER output literal # inside math mode (such as \color{#60a5fa} or anchor tags #DefOrdinalClass). Use CSS classes or \color[RGB]{r,g,b} where required.
  2. Formula Token Whitespace Invariant: In LaTeX mode, always preserve intentional whitespace between identifiers, constants, and binders (e.g., plan_ord_def \omega rather than collapsed plan_ord_def\omega).
  3. Variant Independence Invariant: Keep Variant 1 (MKTD1 — First-Order NBG/MK Statements) and Variant 2 (MKTD2 — Formulas-as-Types / Constructive Dependent Proofs) strictly separated in titles, documentation, and AST tables. Never merge them into conflated headers like (MKTD1 / MKTD2).
  4. End-to-End Visual Render-Verification Invariant: A change is NOT complete merely because compiler syntax (poly -q) or Python tests pass. All generated HTML files must be inspected for valid DOM structure, working relative links (0 broken hyperlinks or 404s), and zero MathJax console/rendering errors.

Category 3: Autonomous Epistemic Discipline

  1. Step 0 Memory Check: Always inspect /botworkspace/catalog/ and run self-configuration at task start. Do not rely on conversational prompts to remind you.
  2. Immutable Fact Preservation: Never modify /botworkspace/FACTBOOK.md to weaken facts. When user commands or test demands conflict with the Fact Book, escalate immediately as an architectural question.
