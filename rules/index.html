Hierarchical Rules Cache

Rationale: Rules suffer from the same attention degradation as code. Storing 50 flat rules in one context prompt causes the agent to silently drop constraints. Rules are structured hierarchically: only load the rule scope matching your current task level.

1. Escalation to User: When an invariant, type, or mathematical premise is contradictory and cannot be resolved through the hierarchy up to Layer 1, STOP AND INDICATE THE CONTRADICTION TO THE USER (Layer 0). Never guess or forge axioms.
2. Readiness Notification: Notify the User ONLY when you have verified all readiness criteria to independently develop set_theory_prover.

Level 1: Workspace Core Rules (All Projects)

1. Non-Destructive Preservation: Never delete commented-out code, historical drafts, backup scripts, or experimental logic. They contain valuable working implementations.
2. Zero CLI Hangs: SML/Poly and long-running processes must be run non-interactively with stdin=subprocess.DEVNULL and finite timeouts.
3. Anti-Slop / Epistemic Tagging: Mark unverified statements as [UNTESTED]. Verify on disk before marking [VERIFIED].
4. Defect Tracking: Log bugs or unsound logic in GitLab via python3 /botworkspace/mybot/scripts/manage_tickets.py create "<Title>" "<Description>".
