Unified Notion Ontology

This ontology defines the ground-truth definitions, non-circular distinctions, and prohibited aliases across all workspace systems.

1. Domain: Set Theory

IDCanonical TermDefinition and Distinctions
NOTION:CLASS Class A collection in the domain of discourse of Morse-Kelley (MK) or NBG class theory. All class-expression terms denote classes. A class cannot be free or bound; only syntactic variables ranging over classes can be free or bound. Distinguished from Set and Class_Expre.
NOTION:SET Set A class x that belongs to at least one class: isSet(x) ⇔ ∃ Y, x ∈ Y. In MK and NBG, sets are precisely the elements of the universal class V. Object language defaults to sort Class; sethood is predicated.
NOTION:PROPER_CLASS Proper Class A class X that does not belong to any class: ¬ isSet(X) ⇔ ∀ Y, X ∉ Y. Under von Neumann's limitation of size, a class is proper iff it admits a bijection with V. Cannot be members of Kuratowski pairs.
NOTION:CLASS_VS_SET_VS_EXPRE Class vs Set vs Class Expression The three-level stratification: (1) semantic Class (all domain collections), (2) semantic Set (elements of V), and (3) syntactic Class Expression (Class_Expre AST in CakeML/PolyML metalanguage). Standard ML stores expressions, not semantic classes (Off-by-One Level Invariant).
NOTION:DUNAEV_TAGGED_PAIR Dunaev Tagged Ordered Pair Universal ordered pair (A, B)_D = ({1} × A) ∪ ({2} × B), where 1={0} and 2={0,1}, defined for arbitrary classes A and B without requiring either to be a set. Satisfies pair injectivity and projections π1((A, B)_D) = A and π2((A, B)_D) = B.
NOTION:KURATOWSKI_PAIR Kuratowski Ordered Pair Classical set-theoretic ordered pair ⟨a, b⟩_K = {{a}, {a, b}}, valid only when a and b are sets. Prohibited for proper classes because forming {{V}} would require V ∈ {V}.
NOTION:TARSKI_GROTHENDIECK Tarski-Grothendieck Universe An inaccessible universe U ensuring strongly inaccessible cardinals, providing semantic domain grounding for higher categories, sheaves, and Grothendieck toposes in MKTD.
NOTION:MORSE_KELLEY Morse-Kelley Class Theory (MK) Axiomatic class theory extending NBG by admitting impredicative class comprehension: class comprehension formulas may contain bound class variables. Higher consistency strength than ZFC/NBG.
NOTION:NBG von Neumann-Bernays-Godel Theory (NBG) Axiomatic class theory with predicative class comprehension: comprehension formulas quantify only over sets, making NBG a conservative extension of ZFC.
NOTION:CLASS_COMPREHENSION Class Comprehension Variable-binding construction {x | φ(x)} forming the class of all sets satisfying φ. In Obelisk, class variables are mandatory in comprehension.

2. Domain: Proof Systems

IDCanonical TermDefinition and Distinctions
NOTION:LCF_KERNEL LCF Architecture Soundness paradigm where theorems are encapsulated in an abstract datatype (thm) whose constructors are strictly the primitive inference rules of the logic. Implemented in program/lcf.ML.
NOTION:SOUNDNESS_INVARIANT Soundness Invariant Inviolable logical invariant: if a theorem object Γ ⊢ φ is constructed, φ is a semantic consequence of hypotheses Γ under the object theory.
NOTION:SEQUENT_CALCULUS Sequent Calculus Proof calculus manipulating sequents of the form Γ ⊢ Δ with explicit left and right introduction rules, cut elimination, and structural rules. Used in newchecker.ML.
NOTION:TABLEAU_CALCULUS Semantic Tableau Calculus Refutation calculus that decomposes formulas into conjunctions and disjunctions along branching trees, searching for contradictory closed paths.
NOTION:RESOLUTION_CALCULUS Resolution Calculus Clausal refutation calculus using unification and resolution to derive the empty clause (contradiction).
NOTION:OFF_BY_ONE_LEVEL_INVARIANT Off-by-One Level Invariant Strict distinction between object-level semantic entities in NBG/MK and metalanguage AST representations in Standard ML. Metalanguage manipulates expressions (Class_Expre, Fm_Expre), not semantic collections.

3. Domain: Metatheory

IDCanonical TermDefinition and Distinctions
NOTION:ELEMENTARY_METATHEORY_E Elementary Metatheory E The unspecified elementary metatheory ranging over IΣ1, PA, T, NBG, and MK. Fixes minimal induction and syntactic manipulation requirements.
NOTION:OBJECT_THEORY_MKTD1 MKTD1-theory / MKTD1-system / MKTD1-framework Axiomatic classical sequent calculus theory (MKTD1-theory), proof assistant system (MKTD1-system / MKTD1-prover), and logical framework (MKTD1-framework) implemented in newchecker.ML and types/typetheory.ML, enriched with stratified types (Fm_Expre, Class_Expre, Stmt, Ctx, Prf).
NOTION:OBJECT_THEORY_MKTD2 MKTD2-theory / MKTD2-system / MKTD2-framework Constructive dependent type theory / Curry-Howard formulas-as-types theory (MKTD2-theory), proof assistant system (MKTD2-system / MKTD2-prover), and logical framework (MKTD2-framework) in program/nbg_compiler.ML. Formulas are types (Prop) and proofs are constructive lambda terms.

4. Domain: Platform & Infrastructure

IDCanonical TermDefinition and Distinctions
NOTION:WORKER Worker One autonomous AI execution process spawned to resolve a specific ticket. Has an assigned entity profile, model, and ticket.
NOTION:PROCESS Process The operating system execution entity identified by an OS PID. A worker runs inside an OS process.
NOTION:PLANNER Planner The autonomous ticket supervisor daemon (autonomous_ticket_planner.py) managing queues, model assignments, rate limits, and provider leases.
NOTION:HARNESS Harness The CLI execution front-end wrapping LLM interaction and tool execution runtime (botharness, opencode, agy).
NOTION:TICKET Ticket A task specification markdown file stored in a tickets directory describing a discrete engineering or proof objective.
NOTION:ISSUE Issue The GitLab database representation of a ticket (local-gitlab/data/issues.json). Rendered as an Issue in the GitLab web UI.
NOTION:QUESTION Question An explicit epistemic or architectural escalation requiring human operator guidance, recorded in questions_for_user.html.
NOTION:WORKER_STATE_LIFECYCLE Worker State Lifecycle The canonical lifecycle of a worker: starting to in progress to terminal state (completed, failed, or timeout).
